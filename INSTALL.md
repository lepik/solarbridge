# Установка SolarBridge 1.0.1

Пошаговая инструкция. Обзор возможностей и конфигурации — в [README.md](README.md); английская версия — [INSTALL.en.md](INSTALL.en.md).

## Требования

| Машина | Что нужно |
|---|---|
| Мастер (у инвертора) | Linux с systemd (Debian/Raspbian/Ubuntu), Python 3.10+, USB-RS485 адаптер, подключённый к шине инвертора HIDEN HS-20-5548 PRO |
| Приёмник (VPS/вторая машина) | Linux с systemd, Python 3.10+, публичный адрес, доступный мастеру |

- Внешних зависимостей, кроме `pyserial>=3.5`, нет: стандартная библиотека, SQLite, venv.
- Права: установка выполняется с `sudo` (создание пользователя `sbridge`, venv, systemd-служба). Дальше служба работает от непривилегированного пользователя.
- Время: держите NTP на мастере — кадры помечаются временем мастера.

## Распаковка

Пакет — кумулятивный zip (обновляется целиком). Распакуйте в любой каталог, оттуда и запускается установщик:

```bash
unzip solarbridge-1.0.1.zip -d ~/solarbridge-src
cd ~/solarbridge-src
sudo python3 install.py
```

Никаких аргументов и флагов. Повторный запуск `install.py` на уже установленной машине открывает меню управления (см. ниже).

## Установка: МАСТЕР

Запустите `sudo python3 install.py`, выберите роль **«Мастер — инвертор подключён по RS485, раздаёт кадры приёмникам»** и ответьте на вопросы:

1. **Serial-адаптер.** Установщик сканирует `/dev/serial/by-id/*` и `/dev/ttyUSB*` и предлагает найденное списком. Выбирайте by-id/by-path путь — он переживает смену ttyUSB-номеров при переподключении. Посмотреть карту портов вручную: `ls -l /dev/serial/by-id/` и `ls -l /dev/serial/by-path/`.
2. **Modbus slave id инвертора** — по умолчанию `4` (заводской адрес HIDEN HS-20-5548 PRO).
3. **Скорость порта** — по умолчанию `19200`.
4. **Порт дашборда** — по умолчанию `8090`. Мастерская машина обычно не выставляется в сеть: дашборд мастера слушает `127.0.0.1`.
5. **Глубина истории** — по умолчанию `730` дней (~7,6 ГБ при 60-сек кадре).
6. **Окно догрузки для приёмников** — по умолчанию `60` дней.
7. **Батареи (экспериментально)** — по умолчанию выключено. Если согласитесь: порт отдельного адаптера шины батарей и DIP-адреса модулей (например `2,3`; автоскана нет).
8. **Минимальный свободный процент диска** — по умолчанию `10`. Ниже порога мастер прекратит писать в свою БД и будет слать кадры только приёмникам (на дашборде появится предупреждение). `0` — не проверять.
9. **Вход по логину/паролю** — по умолчанию выключено. Если включите: задайте логин и пароль — они будут записаны в файл `user_list` (формат `login:password`, открытый текст, права 0640), а в `.env` появится `SB_AUTH=1`. После первого входа браузер запоминает токен на 30 дней.

Дальше установщик сам: генерирует `master_id` вида `hostname-XXXXXXXX` (случайный суффикс, защита от «подставного» мастера; записывается в `.env` и с этого момента не меняется), создаёт пользователя `sbridge` (группа `dialout`), каталог `/opt/solarbridge`, venv, ставит `pyserial`, пишет `/opt/solarbridge/.env`, создаёт пустой `receivers.list`, ставит systemd-службу `solarbridge.service` и ждёт ответа `/healthz` до 30 с. В конце печатает:

```
SolarBridge 1.0.1 установлен и работает: http://127.0.0.1:8090
```

## Установка: ПРИЁМНИК

На VPS: распакуйте тот же zip, `sudo python3 install.py`, роль **«Приёмник — принимает кадры от мастера»**:

1. **Токен** — печатается на мастере при добавлении приёмника (см. ниже). Ожидается 64 hex-символа.
2. **Порт дашборда** — по умолчанию `8090`. Визард приёмника ставит `SB_DASH_HOST=0.0.0.0` — приёмник должен быть доступен мастеру напрямую. Если приёмник прячется за nginx — подтвердите это в шаге 4 и поставьте `SB_DASH_HOST=127.0.0.1` в `.env` (пункт меню «Настройка .env»).
3. **Глубина истории приёмника** — по умолчанию `730` дней.
4. **IP-allowlist** — CIDR через запятую (например `203.0.113.10/32`); Enter = выключено. Список проверяется до токена.
5. **«Приёмник за nginx (доверять X-Forwarded-For)?»** — отвечайте «да» только если действительно ставите nginx спереди; тогда `SB_TRUST_PROXY=1`.

## Что делает установщик (обе роли)

- копирует проект в `/opt/solarbridge` (существующие `data/` и `.env` не трогает; повторная установка = обновление файлов);
- создаёт системного пользователя `sbridge`, добавляет его в группу `dialout` (доступ к USB-serial);
- создаёт venv и ставит `pyserial` из `requirements.txt`;
- создаёт `data/` и `data/seeds/`;
- пишет `.env` (backup старого в `.env.bak`), права `0640` на `.env` и `receivers.list`, `0750` на `data/`;
- устанавливает `/etc/systemd/system/solarbridge.service`, `daemon-reload`, `enable`, `restart`;
- ждёт `http://127.0.0.1:<порт>/healthz`.

## Меню управления (повторный запуск install.py)

На мастере:

1. Статус пересылки (по каждому приёмнику: вкл, состояние, водяной знак, сбои, отправлено/принято)
2. Добавить приёмник
3. Управление приёмниками (вкл/выкл, смена токена, удаление)
4. Создать пересев (seed)
5. Активные seed-ссылки (и отзыв)
6. Восстановить данные из базы приёмника (умерла SD-карта мастера)
7. Обслуживание базы: удалить данные до даты (с VACUUM)
8. Диагностика
9. Служба (старт/стоп/рестарт/статус/журнал)
10. Перенастроить роль и параметры

На приёмнике: статус (мастер жив/ошибка шины/offline, версия мастера, свежесть heartbeat, последний кадр, события) · скачать пересев по ссылке · настройка `.env` · диагностика · служба · перенастройка.

Правила меню: выбор номером, `Enter` = безопасный дефолт, опасные действия требуют подтверждения (дефолт — «нет»).

## Восстановление мастера из базы приёмника

Сценарий: SD-карта мастера вышла из строя. Данные не потеряны — каждый приёмник хранит полное зеркало.

1. Установите SolarBridge на новую карту как обычно (роль «Мастер»; новый `master_id` генерируется с суффиксом).
2. Скопируйте базу приёмника на мастера:
   ```bash
   scp user@receiver:/opt/solarbridge/data/solarbridge.sqlite3 /tmp/rx.sqlite3
   ```
3. `install.py` → **«Восстановить данные из базы приёмника»** → путь к файлу → режим переноса:
   - **«Всё»** — переносится вся история приёмника;
   - **«Диапазон дат»** — с даты по дату включительно;
   - **«С даты до конца»** — кадры выбранной даты и новее.
4. Установщик сделает бэкап текущей базы, перенесёт кадры и батарейные строки с дедупликацией (повторный запуск безопасен) и вернёт службу.

Потери ограничены хвостом данных за время, пока новый мастер ещё не начал писать (минуты). Подробнее — раздел «Восстановление мастера с нуля» в README.md.

## Serial-порты: by-id и by-path

Два адаптера (инвертор + батареи) могут меняться местами как `ttyUSB0/1` после переподключения. Используйте стабильные пути:

```bash
ls -l /dev/serial/by-id/     # серийник адаптера — самый стабильный
ls -l /dev/serial/by-path/   # физический порт USB
```

systemd-юнит из `deploy/solarbridge.service` держит `DevicePolicy=closed` с `DeviceAllow=char-ttyUSB rw` — все `ttyUSB*` доступны, а если адаптер перечислился как ttyACM (CDC-ACM), добавьте `DeviceAllow=char-ttyACM rw`.

## nginx (приёмник за HTTPS)

Сценарий: приёмник на VPS, дашборд доступен по HTTPS, ingest-трафик мастера идёт через тот же адрес. В `.env` приёмника: `SB_DASH_HOST=127.0.0.1`, `SB_TRUST_PROXY=1`.

```nginx
server {
    listen 443 ssl http2;
    server_name vps1.example.com;

    ssl_certificate     /etc/letsencrypt/live/vps1.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/vps1.example.com/privkey.pem;

    location / {
        proxy_pass         http://127.0.0.1:8090;
        proxy_http_version 1.1;
        proxy_set_header   Host $host;
        # ВАЖНО: перезаписывать, а не добавлять — иначе клиент может
        # подделать первую запись X-Forwarded-For и обмануть allowlist
        proxy_set_header   X-Forwarded-For $remote_addr;
        # SSE (/api/events): отключить буферизацию
        proxy_buffering    off;
        proxy_read_timeout 65s;
    }
}

server {
    listen 80;
    server_name vps1.example.com;
    return 301 https://$host$request_uri;
}
```

URL приёмника в `receivers.list` мастера — `https://vps1.example.com` (без порта и без слэша в конце).

Если дашборд должны смотреть только вы, добавьте basic auth в nginx:

```nginx
auth_basic "SolarBridge";
auth_basic_user_file /etc/nginx/solarbridge.htpasswd;
```

## nftables: открываем порты осознанно

Порт приёмника задаётся один раз в `.env` приёмника — `SB_DASH_PORT` (по умолчанию `8090`). Мастер шлёт POST-запросы на три endpoint'а этого порта:

```
POST {url}/api/ingest/hello       # рукопожатие: обмен схемой и меткой последнего сэмпла
POST {url}/api/ingest/frames      # кадры телеметрии (gzip)
POST {url}/api/ingest/heartbeat   # heartbeat каждые 15 с
```

### Вариант 1: приёмник напрямую (без nginx)

Сервис слушает `0.0.0.0:8090`. Откройте порт **только для IP мастера** — это одновременно и защита дашборда, который в этом варианте не имеет своей аутентификации:

```nft
# /etc/nftables.conf (фрагмент input-цепочки)
table inet filter {
    chain input {
        type filter hook input priority filter; policy drop;

        iifname "lo" accept
        ct state established,related accept

        # ваш SSH — оставьте как настроено
        tcp dport 22 accept

        # SolarBridge: ingest + дашборд, только с IP мастера
        ip saddr 203.0.113.10 tcp dport 8090 accept
        # если мастер доступен по IPv6:
        # ip6 saddr 2001:db8:1::10 tcp dport 8090 accept
    }
}
```

Применение и автозагрузка:

```bash
sudo nft -f /etc/nftables.conf
sudo systemctl enable nftables
```

Если мастер ходит через NAT/динамический адрес — дополнительно воспользуйтесь app-level allowlist `SB_INGEST_ALLOWLIST` (CIDR) на приёмнике, но помните: GET-роуты дашборда остаются публичны для остальных IP.

### Вариант 2: приёмник за nginx (рекомендуется для VPS)

Открыты только `80/443`; сервис на `127.0.0.1:8090` наружу не слушает:

```nft
table inet filter {
    chain input {
        type filter hook input priority filter; policy drop;
        iifname "lo" accept
        ct state established,related accept
        tcp dport 22 accept
        tcp dport 80 accept   # redirect на HTTPS
        tcp dport 443 accept  # дашборд + ingest через nginx
        # tcp dport 8090 — НЕ открывать никому
    }
}
```

Права IP-мастера при этом проверяются на уровне приложения (`SB_INGEST_ALLOWLIST`) либо basic auth'ом nginx.

### Мастер

Дашборд мастера по умолчанию слушает `127.0.0.1` — наружу открывать нечего. Если хотите смотреть его с другого устройства, поставьте nginx/SSH-туннель (`ssh -L 8090:127.0.0.1:8090 master-host`) вместо `SB_DASH_HOST=0.0.0.0`: на мастере нет аутентификации на GET-роутах.

## Развёртывание нового приёмника

**Вариант А — без истории (самый частый).** Мастер сам зальёт приёмнику до 60 дней истории при первом подключении.

1. На мастере: `install.py` → **«Добавить приёмник»**: имя (например `vps1`) → URL (`https://vps1.example.com` или `http://203.0.113.10:8090`). Токен генерируется автоматически, строка пишется в `receivers.list`, а готовый `.env`-блок сохраняется в `data/seeds/env-<имя>.txt` (права 0600). Сразу можно проверить связь (`hello`-проба; если приёмник ещё не установлен — это нормально, мастер повторит сам).
2. На VPS: распакуйте zip, `sudo python3 install.py`, роль «Приёмник», вставьте токен из `env-<имя>.txt`.
3. Готово: мастер дозагрузит окно истории автоматически (~10 минут для полных 60 дней).

**Вариант Б — с историей глубже окна (пересев по сети).**

1. На мастере: `install.py` → **«Создать пересев»** → компактный (~190 МБ за 60 дней) или полный. Установщик печатает одноразовую ссылку вида `http://…/api/seed/download/<id>?t=…` (живёт 24 ч, до 10 скачиваний, докачка при обрыве).
2. На приёмнике: `install.py` → **«Скачать пересев по ссылке»** → вставить ссылку. Приёмник проверит sha256, свежесть (`SB_SEED_MAX_AGE_DAYS`) и схему, сделает бэкап, развернёт снимок и перезапустится.
3. Мастер сам дошлёт кадры, накопившиеся за время копирования.

Активные seed-ссылки и отзыв — пункт меню «Активные seed-ссылки».

**Вариант В — переезд существующего приёмника.** Скопируйте только его `data/solarbridge.sqlite3` (это данные, не секреты) и напишите свой `.env`. Копировать на приёмник **нельзя**: `receivers.list` мастера (там токены) и мастерский `.env`.

## Обновление SolarBridge

**Способ 1 — `update.py` (рекомендуется).** Скрипт входит в состав пакета (и остаётся в `/opt/solarbridge/update.py` после установки):

```bash
sudo python3 update.py --check                 # сравнить версии (установлена/доступна)
sudo python3 update.py                         # скачать релиз (SB_UPDATE_URL или --url), проверить sha256,
                                               # бэкап, применить, рестарт, healthz; откат при неудаче
sudo python3 update.py --from solarbridge-1.1.0.zip   # офлайн, локальным файлом
```

Источник релиза — `SB_UPDATE_URL` в `.env` (репозиторий GitHub или прямой URL zip). `.env`, `data/`, `receivers.list` и `.venv` не перезаписываются никогда; бэкапы — в `backups/` (хранятся последние 2). Даунгрейд — только с `--force`. Если после обновления служба не поднялась по `/healthz` за 60 с, `update.py` сам восстанавливает бэкап и перезапускает службу.

**Способ 2 — вручную.** Распакуйте новый zip поверх (или рядом) и запустите установщик:

1. Распакуйте новый zip рядом (или поверх) — установщик обновит файлы в `/opt/solarbridge`, не трогая `data/` и `.env`.
2. `sudo python3 install.py` — найдёт существующий `.env`, обновит код, перезапустит службу.
3. Несовпадение схемы БД: мастер «новее» приёмника — приёмник отвечает `409` и хранит свои данные; после обновления приёмника догрузка продолжится.

В обоих случаях держите версии мастера и приёмника одинаковыми: при расхождении дашборд показывает баннер-предупреждение (версия мастера приходит с heartbeat).

## Диагностика

- **Журнал службы**: `journalctl -u solarbridge -n 100 -f`.
- **Быстрая проверка**: `curl http://127.0.0.1:8090/healthz` → `{"status":"ok"}`.
- **Состояние мастера глазами приёмника**: `curl http://127.0.0.1:8090/api/master` (на приёмнике) — состояние, версия мастера, последние события (`master_events`, хранятся 30 дней): `master_alive`, `master_offline`, `bus_error`, `bus_ok`, `schema_mismatch`.
- **Статус пересылки** (мастер, пункт меню 1): водяной знак = самое свежее, что приёмник подтвердил (acked); сбои и последняя ошибка.
- **Ошибка шины RS485** на дашборде — проверьте кабель/терминацию; мастер продолжает опрос и сам восстановится.
- Приёмник отстал глубже окна догрузки — нужен пересев (Вариант Б).
- Порт занят: смените `SB_DASH_PORT` в `.env` и перезапустите службу.

## Удаление

```bash
sudo systemctl disable --now solarbridge
sudo rm /etc/systemd/system/solarbridge.service
sudo userdel sbridge
sudo rm -rf /opt/solarbridge
```
